2What the file means

Each record gives, for one SKU: NAME exactly as written; PRICE_VND as a positive whole number copied exactly (leading zeros removed, no currency conversion); QTY_ON_HAND as physical unsold units on hand, including units currently reserved by shop orders — not "available to sell" and not a change (+/−). An accepted file replaces the whole supplier snapshot.

  • First line exactly SKU,NAME,PRICE_VND,QTY_ON_HAND. UTF-8 text; one byte-order mark at the start is allowed. LF or CRLF line endings.
  • At most 1 MiB (1048576 bytes) and 10000 product records.
  • SKU: 1–32 of A–Z 0–9 - _ (no automatic upper-casing). NAME: 1–120 characters, kept exactly. PRICE_VND ≥ 1 and QTY_ON_HAND ≥ 0, digits only.
  • All or nothing: one problem anywhere means no snapshot is produced. Each SKU may appear only once.

    Who decides what in this tool
    • Accept or reject, and every listed problem: the shared supplier definition supplier.from_csv in the pinned DNode kit — the same definition the shop uses.
    • Explanations, counts and the snapshot bytes: this tool's DNode root batch.node. It never changes the verdict or the problem list.
    • Reading CSV: the kit's pinned CSV reader (a host-implemented native). It cannot say where a broken quote is.
    • This browser: reads the file, checks the 1 MiB limit before reading any records, decodes UTF-8 strictly, computes SHA-256 run identities and offers new files to download. It never overwrites a file; each export has its run ID in its name.
