## Purpose

An operator turns a legacy supplier CSV into validated shop inventory records and understands exactly what was accepted or rejected; never wonders whether a failed run partially changed anything. No live stock mutation.

## Experience

Mistakes are explainable and correction is easy: the declared meaning is on the page, every rejected record is named with its text, the field and what to do; the text is editable in place and re-run; exports are published together with their hashes and a run ID.

## Journey

choose CSV (or paste) → declared meaning → validate → records to correct / duplicates / preview → export normalised snapshot and report.

## Domain

UTF-8 CSV, optional BOM, header exactly SKU,NAME,PRICE_VND,QTY_ON_HAND, LF/CRLF, quoted commas/newlines/doubled quotes; SKU 1–32 [A-Z0-9_-]; NAME 1–120 scalars preserved; PRICE_VND digits → exact positive integer; QTY_ON_HAND digits → exact non-negative integer (physical unsold units incl. reserved); limits 1 MiB before parsing, 10000 data rows after lexical parsing.

## Behavior

broken quote rejects the file (BrokenQuote); bad header → BadHeader; >10000 rows → TooManyRows; any invalid record or duplicate SKU → Rejected with located diagnostics (record, field, problem); header-only → Rejected (empty); Accepted → records sorted by SKU, integers as numbers, in the pinned export encoding (native encode = the substrate canonical form); the report never contains a volatile value.
