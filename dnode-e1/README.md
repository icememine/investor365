# DNode E1 package (v0.4-e1-apps)

Everything here is executable or generated. Nothing in this folder is a rule an author must remember; it is a rule a program enforces.

## Layout
- `substrate/` — `engine.js` (runtime), `natives-text.js` (CSV/text natives + `file.export`), `lang.js` (parser), `check.js` (checker: examples, generated tier, contracts, profile checks, signed certificates), `lock.js` (reissue `natives.lock.json`), `translate.js` (generated dictionary). Copies of `engine.js`, `lang.js`, `natives-text.js`, `check.js`, `translate.js` sit at the top level so the scripts run from here.
- `natives.lock.json` — pinned identities of the 49 natives (impl + contract + examples). A native that is missing, changed, or unlisted denies admission, in the checker and in the host.
- `profiles/` — `pure`, `panel`, `canvas`, `batch` manifests: entry points, effect grants, allowed natives, host obligations, limits. Enforced at check time and at dispatch.
- `kernel/` — `KERNEL.md` (K01–K12, ≤150 lines), `kernel.node` (paired cases), `oracle.py` → `oracle.json` (independent exact-integer oracle), `compare_oracle.js`.
- `roots/` — shared library: `lib_bounded`, `lib_text`, `lib_sequence`, `supplier_snapshot` (domain root), `lib_test` (uses all four), `batch_transform` (BP-BATCH reference app).
- `fixtures/` — 15 supplier files, `expected.json` computed independently in Python, `run_fixtures.js`.
- `docs/` — `DICTIONARY.generated.md` + `dictionary.json` (generated; do not edit), `dictionary.fixture.json` + `test_dictionary.js`.
- `apps/shop/` — BP-SHOP: `shop_stock`, `shop_cart`, `shop_orders`, `shop_import`, `shop` (generated by `gen_shop.py` so the whole-state examples stay consistent). 153 certified under the panel profile.
- `apps/game/` — BP-GAME: `bk_physics` (declared collision policy in its header), `breakout`. 44 certified under the canvas profile.
- `roots/batch_transform.node` — BP-BATCH (49 certified under the batch profile).
- `host/` — generic hosts: `shop.src.html` (panel profile: item kinds, session state, payment simulator with a test-readable ledger, request fulfilment), `game.src.html` (canvas profile: fixed 60 Hz tick, catch-up limit, trace record/replay, delay and render-fault injection), `batch.src.html` (batch profile: byte limit before parsing, staged-then-published exports, run ID), `panel.src.html` (the first generic page), and `build.js`.
- `fixtures/shop/` (supplier files for the shop desk), `fixtures/game/` (`policy.py`: an independent implementation of the declared collision policy → `traces.json`; `run_traces.js` compares the certified graph: 8/8 agree).
- `work/test_shop.js`, `test_game.js`, `test_batch.js` — headless Chromium drives of S01–S08, G01–G05, B01–B06 → `docs/evidence.*.json` and `docs/shots/*.png` (390×844).
- `docs/records.js` → `docs/RECORD-{shop,game,batch}.md` + `records.json`: the §2 blueprint records, generated from certificates and evidence; human acceptance stays pending until a reviewer records it.
- `HUMAN-TESTING.md` — what to do on a phone, and how to record acceptance.

## Reproduce
```
DNODE_ROOTS=kernel node check.js kernel                 # 17 certified, 5 demonstrated
node kernel/compare_oracle.js                           # 44 cases, 0 disagreements with the Python oracle
DNODE_ROOTS=roots node check.js lib_test                # 29 certified
DNODE_ROOTS=roots node check.js batch_transform batch   # 49 certified under the batch profile
node fixtures/run_fixtures.js                           # 15 agree, 0 disagree
DNODE_ROOTS=roots:apps/shop node check.js shop panel    # 153 certified
DNODE_ROOTS=roots:apps/game node check.js breakout canvas   # 44 certified
python3 -I fixtures/game/policy.py && node fixtures/game/run_traces.js   # 8 agree, 0 disagree
node translate.js && node docs/test_dictionary.js       # dictionary: 50 natives, 225 nodes
node host/build.js shop panel "Pencil & Paper" shop.src.html
node host/build.js breakout canvas "Breakout" game.src.html
node host/build.js batch_transform batch "Supplier snapshot transformer" batch.src.html
node work/test_shop.js && node work/test_game.js && node work/test_batch.js   # 20/20, 16/16, 13/13 (needs playwright + chromium)
node docs/records.js                                    # the three blueprint records
```
`DNODE_ROOTS=dir1:dir2` adds directories searched for `.node` files. `checker.key.json` is the checker's private key: generated on first run, never committed.

## Substrate changes made while building the three applications (all re-verified: kernel, oracle, library, batch, shop, game)
- `engine.js`: environments are null-prototype scopes with the constants on the prototype; path segments cached; profile grants/natives as sets. 42 → 3.3 ms per game tick. Checker identity changed; every certificate reissued.
- Native `encode` added (the substrate's canonical form exposed as the pinned export encoding); lock reissued `49216d6c0fe5a501` → `35330f94bfe082a0` with a note; allowed in the batch and panel profiles.
- Canvas profile: entry `frame(state, event)` on a fixed tick (was `frame(state, keys, dt, tick)`); host obligations written into the manifest (60 Hz, ≤3 catch-up ticks, no ticks while paused, trace).
- Panel profile: host obligations for session state, item kinds and the payment-simulator protocol (`state.request` → `payment_result` / `inquiry_result`) written into the manifest.
- `batch_transform`: row limit before any ranged work, raw rows for diagnostics, report + snapshot exports.

## Findings from the three builds
- The whole-state example problem: event nodes take the whole state, so every example carries a full state. `gen_shop.py` assembles them from one fixture set; the generated `shop.node` is the source. A `fixture` directive naming a shared example value would remove the generator (candidate, not built).
- A refusal inside a contract is a fault (K08), so every predicate used in a `pre` had to be made total (`state_ok`, `cart_ok`, `line_ok`); the generated tier found each case where it was not.
- No fold: joining text, finding a maximum and sorting are written as map/filter/pairs over helper nodes; `join_fields` is bounded to the schema width. Recursion is refused (`cycle`). Recorded, not worked around.
- InsufficientStock cannot be reached from a valid state because the cart is validated against availability at every step; the `raises` was removed rather than kept as decoration (S04 rests on the invariant, not on a refusal).
- CSV framing (`data_records`, `with_index`, `item_after`, `drop_first_item`) is duplicated in `shop_import` and `batch_transform`: a promotion candidate for a shared `lib_csv` root.
- The game's collision policy had to change once during authoring: bricks with a 400 gap let the ball overlap two rows at once; the gap is now wider than the ball (1300 > 1200), so at most one brick is overlapped per tick. Declared in the root header and tested by the independent traces.

## Findings carried forward
- `demo` nodes: examples that must pass but are never callable (status `demonstrated`); needed for kernel cases whose point is a fault.
- `to_int` domain widened to the safe-integer range with a precondition; the change was caught by the lock and reissued with a note.
- A total `sum_exact` wrapper is impossible under exact integers; the pinned native `sum` is the definition.
- Paths on call results (`(f x).field`) are not grammar; lets or helper nodes (finding F7, recurring).
- The generator found four missing preconditions in `supplier_snapshot` (`index_ok`, unique SKUs for `at_position`, lower bounds on `with_index`/`item_after`); impossible `raises` were removed rather than kept as decoration.
- Still open from Astra's plan: K07 typed inputs, K05 canonical byte spec, K11 payload validation, K12 digest/trust policy, standard-root promotion policy, shop/game regressions on this substrate.
